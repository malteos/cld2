# Reverse Engineering CLD2's Quadgram Scoring Tables

## Overview

CLD2's language detection relies on pre-computed quadgram scoring tables generated by an offline training pipeline that is not included in the repository. This document describes how these tables work internally and how we reverse-engineered the format to inject new languages.

## Table Architecture

CLD2 uses a **4-way associative hash table** to map quadgrams (4-character sequences) to language probabilities:

```
Text Input
    |
    v
QuadHashV2() ──> hash value
    |
    v
IndirectProbBucket4[bucket_count]   ── kQuad_obj.kCLDTable
    |  (4 entries per bucket, each: hashkey | indirect_subscript)
    v
kCLDTableInd[indirect_subscr]       ── kQuad_obj.kCLDTableInd
    |  (langprob: 3 languages + probability subscript)
    v
kLgProbV2Tbl[prob_sub * 8]          ── probability lookup
    |  (3 probability values: 1-12 log scale)
    v
Tote.Add(pslang, probability)       ── accumulate scores
```

## Key Data Structures

### langprob (uint32)

The core unit of the scoring tables. Encodes 3 language candidates and a probability pattern:

```
Bits [31:24] = lang3     per-script language number (0 = unused)
Bits [23:16] = lang2     per-script language number
Bits [15:8]  = lang1     per-script language number
Bits [7:0]   = prob_sub  index into kLgProbV2Tbl (240 entries)
```

Decoding:
```python
prob_sub = langprob & 0xFF
lang1 = (langprob >> 8) & 0xFF
lang2 = (langprob >> 16) & 0xFF
lang3 = (langprob >> 24) & 0xFF
```

### IndirectProbBucket4

Each hash bucket contains 4 entries:
```c
struct IndirectProbBucket4 {
    uint32 keyvalue[4];  // 4-way associative
};
// Each keyvalue = (hashkey & keymask) | (indirect_subscript & ~keymask)
```

### Indirect Table Modes

Entries below `kCLDTableSizeOne` store **one langprob** (3 languages).
Entries at or above `kCLDTableSizeOne` use double-width: **two consecutive langprobs** (6 languages).

```
subscript < SizeOne:  kCLDTableInd[subscript]          = one langprob
subscript >= SizeOne: kCLDTableInd[subscript + delta]   = langprob1
                      kCLDTableInd[subscript + delta+1] = langprob2
where delta = subscript - SizeOne
```

### Probability Table (kLgProbV2Tbl)

240 entries, each 8 bytes. Bytes [5:7] are the 3 probability values for 3-language lookups.
Values range from 1 (low confidence) to 12 (high confidence, log2 scale).

Organized in 3 groups of 78 entries each:
- Group 0 (0-77): mid = average of hi and lo
- Group 1 (78-155): mid = 3/4 toward hi
- Group 2 (156-233): mid = 1/4 toward hi

### Hash Function (QuadHashV2)

```python
def quad_hash_v2(word_bytes, offset, length):
    prepost = 0
    if offset > 0 and word_bytes[offset-1] == ord(' '):
        prepost |= 0x00004444
    if offset + length < len(word_bytes) and word_bytes[offset+length] == ord(' '):
        prepost |= 0x44440000
    return quad_hash_v2_mix(word_bytes[offset:offset+length], length, prepost)
```

Bucket selection: `subscr = (hash + (hash >> 12)) & (bucket_count - 1)`
Key matching: `(hashkey ^ entry) & keymask == 0`

## The Injection Technique

### Problem

New languages added to kQuad_obj2 (secondary table) are outscored by established languages in kQuad_obj (main table). For French Creoles: Haitian Creole gets ~100 quadgram hits from the main table vs ~10 for Saint Lucian Creole from the secondary table.

### Solution

Modify kCLDTableInd entries in kQuad_obj directly:

1. **Parse** the C++ source to extract all uint32 langprob values
2. **Find** entries containing the confusable language (e.g., hat = pslang 83)
3. **Check** for empty slots (lang = 0) in the 3-language entry
4. **Insert** the new language's pslang into the empty slot
5. **Recompute** the probability subscript to give the new language a fair score
6. **Write** the modified table back as valid C++

### Example

Before injection:
```
langprob = 0x00230653  ->  lang3=0, lang2=35(ca), lang1=6(de), prob=83(hat)
```
Wait — actually the encoding is: `[lang3][lang2][lang1][prob_sub]`, so:
```
langprob = 0x002306XX  where XX = prob_sub
  lang1 = (0x002306XX >> 8) & 0xFF  = 0x06 (pslang 6)
  lang2 = (0x002306XX >> 16) & 0xFF = 0x23 (pslang 35)
  lang3 = (0x002306XX >> 24) & 0xFF = 0x00 (empty!)
```

After injection of acf (pslang 122 = 0x7A):
```
langprob = 0x7A2306XX  ->  lang3=122(acf), lang2=35(ca), lang1=6(de)
```

## Tool: `tools/inject_languages.py`

```bash
# Dry run: see what would be modified
python3 tools/inject_languages.py \
    --input internal/cld2_generated_quad0122.cc \
    --output /dev/null \
    --inject 83:122 \
    --prob 4 \
    --dry-run

# Actual injection
python3 tools/inject_languages.py \
    --input internal/cld2_generated_quad0122.cc \
    --output internal/cld2_generated_quad0122.cc \
    --inject 83:122 \
    --prob 4
```

Arguments:
- `--inject SRC:TGT` — inject target pslang alongside source pslang
- `--prob N` — probability value (1-12) for the injected language
- `--dry-run` — only report changes, don't write output

## Limitations

1. **3-slot limit**: Each langprob entry holds at most 3 languages. If all slots are full, no injection is possible without replacing an existing language.
2. **No new quadgrams**: Injection only adds languages to EXISTING quadgram entries. It cannot create entries for quadgrams not already in the table.
3. **Probability coupling**: The probability subscript encodes a pattern for all 3 languages together. Changing one language's probability affects the others.
4. **One injection per slot**: Once acf fills the empty slot in a hat entry, gcr/gcf cannot also be injected there.
